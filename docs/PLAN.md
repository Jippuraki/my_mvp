# ★ 이번에 만들 것 (확정): 시연용 두 가지

## 목적
수업 발표에서 "입력이 쉽다"와 "알선이 아니다"를 보여 주기 위해서예요. 서버·AI 키 없이 `index.html` 안에서만 만들어요.

## A. 사진으로 프레임 찾기 (시연용)
**바꿀 곳:** `index.html`의 프레임 시트(`frameSheet`, 약 543줄)와 JS의 `renderFrameSheet()`(1037줄).

1. 프레임 시트 맨 위에 **"📷 사진으로 찾기"** 버튼을 넣어요 (검색창 `fsearch` 위).
2. 누르면 **"이렇게 찍어 주세요" 안내 화면**이 먼저 떠요.
   - 밝은 곳, 단색 배경(흰 종이 등)에 놓기
   - 정면에서 테 전체가 보이게 한 장
   - 옆면(다리) 글씨가 보이게 한 장 (선택)
   - 얼굴은 찍지 않기 / 사진은 저장하지 않아요(시연용이라 실제로 업로드 안 함)
   - 간단한 그림(SVG)으로 좋은 예 / 나쁜 예를 보여 줘요
3. 사진을 고르면 **"분석 중…" 1~2초** 후 **가짜 결과**를 보여 줘요.
   - 시연 결과는 기존 `MODELS`(8개) 중 하나를 골라 `state.rim / cat / sub / model`을 채워요. 이미 있는 `renderSearch()`·`updateS1()`을 그대로 써요.
   - "추정이에요. 맞는지 확인해 주세요" + [맞아요] [직접 고칠래요] 버튼
   - 상단에 작게 **"시연용 가짜 분석이에요"** 표시를 꼭 넣어요 (속이지 않기 위해)
4. [맞아요]를 누르면 바로 **"내 프레임 보관함에 넣기"** 로 연결돼요 (아래 B).

## B. 프레임 보관함 (사진 찾기와 연결)
**바꿀 곳:** 프레임 시트 + 메뉴(`renderMenu("main")`, 1105줄) + `state`.

1. 분석 결과 카드와 "선택 완료" 옆에 **"보관함에 넣기"** 버튼을 넣어요.
2. 저장: 이 브라우저의 `localStorage`에 `{이름, 테 모양, 소재, 모델, 사진 미리보기(작게)}` 목록으로 저장해요. 저장이 막혀도 앱은 계속 동작하게 try/catch로 감싸요.
3. 메뉴(≡)에 **"내 프레임 보관함 N개"** 항목을 추가해요. 누르면 목록이 뜨고, 고르면 `state`가 채워져요. 지우기도 가능해요.
4. 프레임 시트 맨 위에 **"최근 쓴 프레임"** 한 줄도 보여 줘요.

## C. 조건 정리 카드 (3번 수정안)
**바꿀 곳:** 문의 메뉴 `renderAsk()`(1282줄)와 그 버튼 처리.

1. 문의 메뉴의 "이 조건으로 정확한 견적 묻기"를 **"📋 내 조건 카드 보내기"** 로 바꿔요.
2. 누르면 프레임·도수(공유 선택 시)·원하는 가공을 한 장으로 정리한 **카드**가 떠요.
3. 카드 아래 버튼: **[복사하기] [전화하기] [카카오톡/문자로 보내기]**. 사용자가 직접 보내요. 앱은 답장을 받지 않아요.
4. 카드와 문의 메뉴에 **"정보 제공만 해요. 가공·결제는 매장과 직접 해요"** 문구를 넣어요.
5. 영어 버전의 "안경원에 보여 주세요" 카드와 같은 컴포넌트로 만들어 나중에 재사용해요.

## D. 교체 주기 · 점검 체크리스트 알림 (보관함 연결) ← 추가됨
**왜:** 가공은 프레임을 살 때만 필요해서 재방문이 적어요. 보관함에 프레임이 있으면 "다음에 할 일"을 알려 줄 수 있어요.

**보관함 항목에 날짜를 더해요**
- 저장할 때 **"렌즈를 맞춘 날"**(선택, 기본값은 저장한 날)을 함께 저장해요.

**알림 두 종류 (일반적인 참고 기준이고 개인 눈 상태에 따라 달라요)**
| 종류 | 언제 | 내용 |
|---|---|---|
| 렌즈 교체·시력 확인 | 렌즈 맞춘 지 약 1년 이상 | "렌즈를 바꿀 때가 됐을 수 있어요. 눈이 피곤하거나 잘 안 보이면 안경원·안과에서 시력을 확인해 보세요" |
| 안경 점검 체크리스트 | 약 6개월마다 | □ 코받침이 헐거워졌나요 □ 나사가 풀렸나요 □ 렌즈에 긁힘이 있나요 □ 코팅이 벗겨졌나요 □ 테가 휘었나요 |

**어디에 보여 주나 (MVP)**
- 화면 1 맨 위 **"🔔 알림 N개"** 카드, 메뉴(≡)의 **"알림"** 항목. 눌러서 체크리스트를 체크하면 "확인했어요"로 다음 알림 날짜가 다시 계산돼요.
- 체크 상태는 `localStorage`에 저장해요 (보관함과 같은 방식).
- **시연용 스위치:** 발표에서 보여 주기 위해 "시연: 13개월 뒤로 보기" 버튼을 둬요. 이 버튼은 날짜를 앞당겨서 알림이 뜨는 모습을 보여 주는 용도이고, 화면에 "시연용"이라고 적어요.
- 진짜 푸시 알림(휴대폰 알림)은 서버·앱 설치(PWA)가 필요해서 **이번에는 하지 않고**, 화면 안 알림으로만 시연해요.

**알선·광고 위험을 피하는 규칙**
- 알림 안에 **특정 안경원을 추천하거나 광고하지 않아요.** "가공 가능한 곳 보기" 버튼은 일반 목록(거리순)으로만 연결해요.
- 알림은 **관리 정보**(교체 시기·점검)만 담아요. 할인·쿠폰은 넣지 않아요. (광고성 정보가 되면 수신 동의 규정이 붙어요)
- 건강 관련 문구는 단정하지 않고 "확인해 보세요" 정도로만 써요.

**바꿀 곳:** 보관함 저장 함수(B), 메뉴 `renderMenu()`, 화면 1 상단(`#progress` 아래에 알림 카드 한 칸), `state`에 `shiftMonths`(시연용).
**확인 방법:** 보관함에 넣기 → 시연 버튼으로 13개월 뒤로 → 알림 카드 표시 → 체크리스트 체크 → 알림이 사라지고 다음 날짜가 갱신되는지 → 새로고침 후에도 유지되는지.

## 내 안경장을 "열리는 안경통"으로 (2026-10-09 아이디어, PR #9 위에 추가 제안)
- **모양:** 평소엔 작게 **닫힌 안경통**(뚜껑 닫힘 + "내 안경장 3/8")만 보여요. 누르면 **뚜껑이 열리며** 칸막이 안에 프레임들이 진열돼요. 보관함 최대 개수(8개)와 맞춰 **2×4 칸**.
- **채워진 칸:** 사진 미리보기(둥근 모양)가 있으면 그 사진, 없으면 우리가 그린 안경 아이콘(풀림·반무테·무테 모양, 소재에 따라 색). **빈 칸:** 점선 + "＋" → 누르면 프레임 추가(기존 흐름).
- **칸을 누르면:** 그 프레임의 카드(별명·렌즈 맞춘 날·메모·찾기)가 아래에 펼쳐져요. 지금 카드 목록은 편집용으로 유지.
- **효과:** 빈 칸이 보여서 "다음 칸 채우기" 수집욕이 생기고, 열린 통 화면은 그대로 **공유 카드**(도수·개인정보 제외)로 쓰기 좋아요. 교체 알림(D)이 생기면 칸에 🔔 표시.
- **주의:** 보내 주신 사진은 상품 사진이라 **그대로 쓰지 않고**, 앱 색에 맞춰 CSS/SVG로 직접 그려요(저작권·용량). 뚜껑 열림은 CSS 애니메이션(가벼움). 접근성: 통은 버튼(`aria-expanded`)으로, 키보드로도 열려요.
- **확인:** 닫힘→열림→칸 누름→빈 칸 추가→새로고침 후 유지, 8개 가득 찼을 때 "＋" 없음.

## 주제를 바꿀까? (2026-10-13 판단)
**결론: 주제 전체를 바꾸지 않아요. 대신 "이번 주 검증 → 기준 미달이면 피벗" 규칙을 먼저 정해요.**

## 임시 회고 (2026-10-14, 초안: 사용자가 고쳐서 쓰기)
**1. 막힌 지점**
- **"돈은 누가 내나"**: 기능을 계속 만들었는데 교수님이 "돈 뭘로 버냐"고 물으셨어요. 사용자는 가공을 가끔만 하고, 안경원에게는 소개 수수료를 받을 수 없어서(알선 걱정) 수익이 막혔어요. 아이디어를 바꿔야 하나 불안했던 시기였어요.
- **알선 걱정**: 후기·견적·예약 같은 기능이 중개로 보일 수 있어서 기능마다 "조건 카드(사용자가 직접 보냄)", "광고·쿠폰 없는 알림"처럼 선을 정해야 했어요.
- **개발 중 막힘(AI와 함께 해결)**: ① 번역 작업 중 `accept="image/*"` 때문에 코드가 통째로 지워진 일 ② 영어 번역이 안 된 것처럼 보였는데 사실 비동기·캐시 때문이었던 일 ③ 화면을 나눈 뒤 1번 화면 버튼이 작아진 일(버튼 이름이 바뀌어서) ④ 보관함이 가득 차면 가장 오래된 것이 조용히 사라지던 일 ⑤ 안경통 이미지가 안 보인 일(PR을 합치기 전이라 배포 주소에 파일이 없었음).
- **팀 의견 차이와 자신감**: 팀원 설득이 어렵고 "이 아이디어가 나쁜가" 하는 의심이 있었어요.

**2. AI에게 어떻게 지시했나**
- 처음엔 작은 지시로 시작했어요(예: "맨 아래에 마지막 수정일 한 줄, 나머지는 그대로"). 그다음엔 "기획하고 제안해줘"처럼 **먼저 계획을 받고 결정은 내가** 하는 방식으로 갔어요.
- **결정 방식**: AI가 선택지를 주면 "B안으로 고정, A안은 없애줘", "도수는 2개만 저장" 같이 짧게 정했어요. 지시를 바꿀 땐 중간에 끼어들어 추가했고(예: 안경통 알림 아이디어), AI가 계획을 먼저 고치고 이어갔어요.
- **작업 규칙**: 기능마다 PR 하나, 내가 "합쳐줘"라고 한 뒤에 합치기, 변경은 계획 파일에 자동 기록, 설명은 쉬운 한국어로. 이 규칙을 정해 두니 반복해서 말하지 않아도 됐어요.
- **그림·화면 요구**: 이미지를 직접 만들어 주고 "이렇게 바꿔줘"라고 했어요(안경통 닫힘·열림, 개수별 8장).
- **사업 고민도 AI와 같이**: 수익모델 표, 경쟁 조사, 피벗 기준, 인터뷰 질문지, 교수님 메일 초안까지 요청했어요.

**3. 느낀 점**
- AI는 만드는 속도는 빠르지만, **무엇을 왜 만드는지(고객, 돈, 검증)는 내가 정해야** 했어요. 기능을 많이 만들수록 "이게 맞는 문제인가"가 더 중요해졌어요.
- **계획 → 확인 → 합치기** 순서로 하니 실수해도 되돌리기 쉬웠어요(배포 주소에 바로 반영되니까 특히 중요했어요).
- AI가 말한 숫자·사실(시장 규모, 가맹 비용 등)은 **확인된 것과 가정을 구분**해서 보게 됐어요. 검색해도 안 나온 건 "모름"으로 남겼어요.
- 가장 큰 배움: 아이디어가 불안할 때는 느낌으로 결정하지 않고 **인터뷰 숫자로 판정 기준을 미리 정하는 것**이 마음을 편하게 했어요. 아버지 의견처럼 좋은 단서도 한 사람의 말이라 5곳 이상 확인하기로 했어요.
- 앞으로: 인터뷰 결과로 판정 → 신청서에 실제 인용·숫자 반영 → 방향 확정 후 MVP2(안경원 프로그램 연결) 검토.

## 2주 고객 검증 계획 (교수님은 수익모델의 설득력을 중시)
**방향**: 주제는 바꾸지 않고 **2주 검증을 피벗 결정 시점**으로 써요. 최종 과제까지 시간이 남아 있어서, 검증이 실패해도 피벗할 시간이 있어요. 교수님이 "설득력"을 보시니 **아이디어 설명보다 증거**(실제 인터뷰 말·지불 의향·사전 신청)를 모아요.
**증거 3종(수익모델 설득력용)**
1. **지불 의향 증거**: 판매자 인터뷰에서 "월 얼마까지"를 직접 묻고 숫자를 적어요. 가능하면 "사전 신청(이메일/연락처 남기기)" 받기
2. **문제 존재 증거**: "가공 때문에 구매를 포기/반품/문의받은 경험" 인용문(익명)과 횟수
3. **공급 현실성 증거**: 안경원 전화 10곳 결과표(가능/불가/조건부, 정보 공개 거부 여부)
**일정(안)**
| 기간 | 할 일 | 산출물 |
|---|---|---|
| 1~3일 | 질문지·전화 스크립트·기록표 준비, 판매자·안경원·마니아 후보 리스트(각 10곳) | 질문지 3종, 기록 시트 |
| 4~9일 | 안경원 전화 10곳, 판매자 인터뷰 5곳, 마니아 인터뷰 5명 | 응답 기록, 인용문 |
| 10~12일 | 결과 정리 → **피벗 기준표**로 판정(유지 / 안경원 구독 부분 피벗 / 주제 피벗) | 판정표 1장 |
| 13~14일 | 비즈니스 모델 1장 요약을 **실제 숫자·인용문으로 업데이트** | 개정된 요약 페이지 |
**판정 기준**(위 "주제를 바꿀까?" 항목과 같음): 판매자 0~1곳만 문제 인식 + 안경원 가공 가능 3곳 미만 → 주제 피벗 / 판매자만 약함 → 안경원 구독 중심 / 둘 다 통과 → 유지
**내가 만들어 줄 수 있는 것(코드 변경 없음)**: 판매자·안경원·마니아 **인터뷰 질문지 3종**, 안경원 **전화 확인 스크립트**, 응답을 모으는 **기록 시트 양식**, 결과를 받으면 **판정표 + 요약 페이지 개정**

## ★ 다음 작업: 비즈니스 모델 1장 요약 페이지 (교수님 제출·발표용)
**목적**: 교수님 두 지적(① 돈은 누가 내나 ② 안경원이 참여할까)에 직접 답하는 **한 페이지**. 앱 코드는 바꾸지 않아요.
**만드는 방법**: 읽기 쉬운 한 페이지 웹 문서(비공개 링크)로 만들어 링크를 드려요. 앱(`index.html`)과 따로 있어요.
**구성(위에서 아래로)**
1. **한 줄 요약**: 외부에서 산 프레임, 어디서 가공할 수 있는지 한 번에 찾는 서비스 + 누가 돈 내는지 한 문장
2. **문제·고객**: 가공 정보 비대칭(발품), 첫 고객(프레임 마니아·수집가·외국인)
3. **돈의 흐름도(그림)**: 판매자 →월 정액→ After Frame →가공 가능 매장 안내·조건 카드→ 구매자(무료) →방문·결제→ 안경원(무료 참여). "앱 안 결제·소개 수수료 없음" 표시
4. **수익모델 표**: 누가 / 왜 내나 / 얼마(가정) / 언제 — 1순위 판매자 위젯 구독, 2순위 안경원 도구·QR 구독, 3순위 사용자 컬렉터 플랜, 브랜드 제휴
5. **안경원이 참여하는 현실성**: 참여 이유(고단가 외부 프레임 손님·정리된 문의·영어 손님) + **참여 없이 시작하는 공급 확보**(공개 정보+전화 확인, 삭제 요청 수용) + 거절당할 때 대안
6. **단위 경제(가정 표시)**: 판매자 20곳 × 월 10만 원 = 월 200만 원, 월 비용 가정(지도·호스팅 등), **손익분기 판매자 수**. 모든 숫자는 "가정·미검증"이라고 명시
7. **검증 계획(이번 주~2주)**: 안경원 전화 확인 10곳, 판매자 인터뷰 5곳, 사용자 인터뷰 5명 + 각각 **성공 기준**(예: 판매자 5곳 중 2곳 이상 지불 의향)
8. **경쟁 차별점**: 지도 앱·기존 안경 서비스는 "외부 프레임 가공 가능 여부"를 못 보여 줘요 → After Frame은 그 한 가지를 정확히
9. **원칙·위험**: 알선 회피 원칙(소개 수수료 없음·앱 안 예약/결제 없음), 개인정보(도수 기본 저장 안 함), 법률 확인 필요 항목
10. **지금까지 만든 것**(앱 화면 5개·기능 요약, 링크) — 실행력 증명
**주의**: 확인된 사실(시장 자료 출처 링크)과 가정을 색/표시로 구분해요. 과장하지 않아요.
**확인 방법**: 폰·PC 폭에서 한 페이지에 읽히는지, 숫자 계산이 맞는지(판매자 수 × 요금, 손익분기), 출처 링크가 열리는지.

## 추후 마일스톤 (이번 PR 4개 이후)
1. **완성품 택배 수령 기능**
   - 가공 후 안경을 택배로 받을 수 있게 해요. 안경원은 **기본 피팅만** 하고, 세부 피팅은 **나중에 재방문**해서 받는 흐름이에요.
   - 정해야 할 것: 택배비 누가 내는지, 파손·분실 책임, 피팅 안내 문구("택배 수령 후 안 맞으면 재방문 피팅"), 수령 후 불만 접수 창구, 택배 추적 표시.
   - 알선 주의: 앱이 결제·배송을 대신 맡으면 중개처럼 보일 수 있어요. **매장이 직접 발송**하고 앱은 상태 안내만 하는 쪽이 안전해 보여요. (법률 확인 필요)
2. **개인 페이지(마이페이지)**
   - 내 프레임 보관함, 교체·점검 알림, 가공 이력, 저장한 안경원, 내 도수 정보를 한곳에 모아요.
   - 정해야 할 것: 로그인 방식, 도수(민감정보) 저장 동의와 삭제, 기기를 바꿔도 이어지는지(지금은 이 기기 안 저장).
   - 지금 만드는 B 보관함과 D 알림이 개인 페이지의 기초가 돼요.
3. **실제 사진 분석** (아래 "실제 분석으로 바꾸려면" 참고) · **장기 수익 모델** (아래 참고)
4. **매장 안 QR 가격 보기 (사장님 도구 아이디어)**
   - 안경원에 QR 스탠드(또는 태블릿)를 두고, 손님이 QR을 찍으면 **그 매장의 렌즈·가공 가격**을 물어보지 않고 볼 수 있어요.
   - 사장님이 가격표를 **한 번만 등록**하면 QR 페이지가 자동으로 만들어져요. 기존 `costItems(shop)`(예상 비용 계산)을 그대로 쓸 수 있어요.
   - 손님 흐름: QR → 프레임 모양·도수 간단 입력 → 이 매장 예상 가격 범위 → [보관함에 저장] / [상담 요청 카드 보여 주기].
   - 사장님 가치: 같은 질문 반복 감소, 상담 시간 절약, 가격 등록 = 공개 동의가 한 번에 됨 → **구독 이유**가 돼요.
   - 알선 위험: 매장 안에서 매장 자기 정보를 보여 주는 도구라서 중개로 보일 가능성이 낮아 보여요. (법률 확인 필요)
   - 걱정: 가격 공개를 꺼리는 사장님 → "정확한 가격" 대신 **범위만 공개** 옵션, 최종 견적은 상담에서. 가격 표시 관련 규정은 확인 필요.
   - MVP 시연: `?shop=A` 같은 주소로 열면 그 매장 가격 화면이 뜨는 화면 1개 + 사장님용 "QR 출력" 화면 예시.

## 실제 분석으로 바꾸려면 (논의 결과)
- **방식:** 서버 함수 1개(Vercel `/api/analyze-frame`)가 사진을 받아 AI 이미지 분석(Claude 등)에 보내고, "테 모양 / 소재 후보 2~3개 / 확신도"를 받아 화면에 채워요. AI 키는 Vercel 환경 변수에만 두고 채팅·코드에 붙이지 않아요.
- **정확도:** 테 모양(풀림/하금/무테)은 꽤 잘 맞고, 소재는 후보만 가능해요. 그래서 확신도 표시와 "매장에서 실물 확인"은 계속 필요해요.
- **필요한 것:** 사진 크기 줄이기(전송 전), 사용 횟수 제한(비용·악용 방지), 실패 시 "직접 고르기"로 안전하게 돌아오기, 사진 저장하지 않기, 개인정보 안내 문구(얼굴 나오면 안 됨).
- **검증:** 실제 프레임 사진 30~50장으로 정확도를 먼저 재 보고 "테 모양 몇 % 맞음"을 숫자로 확인한 뒤에 공개해요.
- **비용 감각:** 사진 1장당 아주 적은 비용이지만 사용자가 늘면 쌓여요. 하루 한도를 두고 시작해요.

## 구현 메모 (코드를 읽고 정리한 것)
- **지금 상태:** 코드는 아직 한 줄도 안 바꿨어요. 작업용 가지 `add-photo-frame-and-condition-card`만 만들어 둔 상태예요.
- **재사용:** `RIMS`, `MATCATS`, `MODELS`(테 정보), `state`, `updateS1()`, `renderSearch()`, `renderFrameSheet()`, `toast(n,msg)`, `openSheet()/closeSheets1()`, 메뉴 `renderMenu()`, 도수 공유 토글(`renderAsk()` 안의 `rxLine`), `fmt()`, `wanted()`, `capName()`. 새 라이브러리는 필요 없어요.
- **새로 필요한 것:**
  - 시트 하나(`photoSheet`) + 숨은 파일 입력(`<input type="file" accept="image/*">`)
  - 보관함 함수 3개(불러오기·저장·삭제). 저장은 `localStorage`, 막히면 메모리로 대체(try/catch)

- **사진 시연 방식:** 사진은 서버로 보내지 않아요. 작은 미리보기(96px)만 만들어 화면에 보여 주고, 결과는 `MODELS` 8개 중 하나를 사진 크기·이름으로 골라 보여 줘요(같은 사진은 항상 같은 결과). 화면에 "시연용 가짜 분석" 표시를 꼭 넣어요. 모델명은 단정하지 않고 **테 모양·소재 후보만** 보여 줘요.
- **보관함 저장 문구:** "사진은 서버에 올리지 않아요. 작은 미리보기만 이 기기에 저장돼요."
- **조건 카드 (결정 반영):** 문의 메뉴에서 `정확한 견적 묻기`는 **조건 카드로 바꿔요**. `메시지로 가공 가능 여부 묻기`는 **사용자 결정에 따라 그대로 둬요**(기존 시연 동작 유지). 남는 항목: 조건 카드, 전화 문의, 메시지 문의. 문자로 보내기는 휴대폰 문자 앱을 열어 주고 받는 사람은 사용자가 직접 골라요. 알선 우려 대응으로 문의 메뉴 아래에 안내 문구를 넣고, 메시지 문의 토스트는 "(예시)"를 유지해요. 나중에 법률 확인 결과에 따라 메시지 항목은 다시 검토해요.
- **바뀌는 줄 수:** 파일 한 개(`index.html`)의 CSS·HTML·JS에 나눠서 추가돼요. 기존 줄은 거의 안 지우고, 문의 메뉴(`renderAsk`와 클릭 처리)만 다시 써요.

## BM·수익·재방문(리텐션) 고민에 대한 의견 (이번 구현 범위 아님)
법적 판단은 제가 확정할 수 없어요. 아래는 방향 제안이고, 실제 서비스 전에는 전문가 확인이 필요해요.

**1. 수수료 대신 쓸 수 있는 수익 방식**
| 방식 | 알선 위험 | 한마디 |
|---|---|---|
| 사장님용 도구 구독료 (견적·가공 가능 항목·가격 관리) | 낮아 보임 | 손님을 소개하는 대가가 아니라 도구 사용료예요. 가장 추천해요 |
| 정액 입점비 | 낮아 보임 | 단, 광고라면 "광고" 표시를 해요 |
| 프레임 브랜드 제휴 ("가공 가능한 곳 인증") | 중간 | 브랜드가 내는 비용이라 손님 소개 수수료와 달라요 |
| ~~건당 소개 수수료~~ | 높아 보임 | **결정: 안경원에게 소개 수수료는 받지 않아요.** 모든 수익 계획에서 제외해요 |

**2. 얼굴형 맞춤 추천 아이디어**
- **좋은 점:** 프레임을 사기 *전* 단계로 앱 사용 시점이 앞당겨져서 재방문 이유가 생겨요.
- **걱정되는 점:**
  - 라운즈가 이미 잘하고 있어서 같은 걸 하면 이길 방법이 없어요.
  - 우리 핵심(가공)에서 멀어져서 앱이 무슨 앱인지 흐려져요.
  - 얼굴 사진은 민감한 개인정보라서 법적·보안 부담이 커요.
  - 추천 → 프레임 구매 연결까지 가면 다시 중개·수수료 문제가 생겨요.
- **제 의견:** MVP에서는 하지 않는 게 좋아요. 대신 **우리만의 방식으로 비틀면** 의미가 있어요: "이 프레임, 내가 원하는 가공(무테·틴팅 등) 되나요?"를 **사기 전에** 확인해 주는 기능. 라운즈가 못 하는 부분이에요.

**3. 재방문(리텐션)이 낮을 수밖에 없는 이유와 대응**
- 가공은 프레임을 살 때만 필요해서 사용 빈도가 낮아요.
- 대응 후보: (a) 프레임 보관함(여러 개 저장) (b) **가공 후기·사진 커뮤니티** — "같은 프레임, 이 가공, 이 가게" 후기가 쌓이면 구경만 해도 올 이유가 생겨요. 얼굴형 추천보다 우리 핵심과 맞아요 (c) 렌즈 교체 시기 알림 (d) 사장님 쪽 도구 구독으로 사장님이 매일 쓰게 하기.
- 커뮤니티 방향이라면 후기 기능(기존 #7)을 다음 순서로 올리는 걸 제안해요.

**4. 제안 순서**
이번 구현(사진 찾기·보관함·조건 카드) → 후기/커뮤니티 시연 → 사장님 도구(구독 BM 검증) → 영어 버전. 얼굴형 추천은 그 뒤에 "사기 전 가공 가능 확인"으로 바꿔서 검토해요.

### 설계 원칙
1. **번역만 하지 않아요.** 한국인용은 "안경원 정보"가 중심이고, 외국인용은 **"소통 가능 여부 + 일정 + 비용"**이 중심이에요.
2. **언어 전환 버튼**을 맨 위에 둬요 (한국어 / English). 처음에는 브라우저 언어를 보고 자동 선택해요.
3. 한국 안경 용어는 영어 옆에 **한글을 같이** 보여 줘요 (무테 = Rimless · 무테). 안경원에서 그대로 보여 줄 수 있어요.

### 외국인 페이지에만 있는 것
- **언어 가능 표시:** "English OK / 中文 OK / 日本語 OK" 태그, 외국인 응대 경험 후기
- **"이 화면을 안경원에 보여 주세요" 카드:** 원하는 가공을 **한국어로 크게** 적은 카드 (예: "무테 가공, 틴팅, 도수 -6.50"). 말이 안 통해도 이 화면 하나로 주문이 돼요.
- **관광객 모드:** "3일 안에 가능한 곳만" 필터, 호텔로 택배 가능 여부, 부가세 환급(Tax Free) 가능 여부
- **도수 쉽게 입력:** 외국 처방전 사진을 올리면 SPH/CYL/AXIS를 읽어 줘요. 한국과 표기가 다른 부분은 설명해요.
- **가격은 원화 + 환산:** ₩ 옆에 대략 USD를 같이 써요. "현장 결제, 카드 가능" 표시도 넣어요.
- **길찾기:** 네이버 지도뿐 아니라 구글 지도 링크도 함께 제공해요 (외국인은 네이버 지도를 거의 안 써요).
- **문의 메시지 자동 번역:** 영어로 쓰면 안경원에는 한국어로 가고, 답은 영어로 돌아와요.

### 화면 흐름 (영어 버전)
1. **Language & Who are you?** 언어 선택 → "I live here / I'm visiting" 선택
2. **My Frame** (한국 버전과 같음, 영어+한글 용어)
3. **Prescription & Lens** (처방전 사진 올리기 추가)
4. **Area & Timing** (지역 + "며칠 머무나요?" 추가)
5. **Shop list** (언어 가능 태그, 빠른 작업 표시)
6. **Shop detail** (+ "Show this to the shop" 카드, 환급·카드 결제 정보)

### 구현 방식 제안
- **방법 A (추천): 한 파일 안에서 언어 전환.** 문구를 `KO`/`EN` 두 묶음 사전으로 모으고 버튼으로 바꿔요. 파일이 늘지 않고 관리가 쉬워요.
- 방법 B: `en/index.html`을 따로 만들기. 외국인용 페이지를 많이 다르게 만들 때 좋지만, 고칠 때 두 곳을 같이 고쳐야 해요.
- **추천:** 처음은 A로 시작하고, 외국인 전용 화면(관광객 모드, 보여 주기 카드)이 커지면 B로 나눠요.

## 4. 해결해야 할 질문 → 사용자 결정 + 제안 (최신)
> 법적 판단은 확정할 수 없어요. 실제 서비스 전에 전문가(변호사, 안경사협회, 창업지원단) 확인이 필요해요.

### 4-1. 안경원 데이터: 웹 정보 수집 + 사장님 직접 등록 (결정)
**데이터를 3단계 신뢰 표시로 나눠요.** 이미 코드에 있는 `verified`(확인 여부) 표시를 넓혀서 써요.
| 표시 | 뜻 | 출처 |
|---|---|---|
| 미확인 | 웹에 공개된 기본 정보만 있음 (이름·주소·영업시간·전화) | 지도 서비스 공개 정보 |
| 확인됨 | 팀이 전화·방문으로 가공 가능 여부를 직접 확인 | 우리 팀 |
| 사장님 등록 | 사장님이 직접 입력·동의 | 사장님 |

- **웹 수집 주의:** 블로그·카페 글을 통째로 긁어오면 저작권·약관 문제가 생길 수 있어요. **공식 지도 API/공공데이터의 기본 정보**만 쓰고, "가공 가능 여부"와 가격은 웹에 거의 없어서 **전화 확인이나 사장님 등록**으로 채워요.
- **수업 발표용 현실적인 범위:** 홍대·연남·신촌 안경원 5~10곳을 팀이 전화로 확인해서 "확인됨"으로 만들어요.

**사장님 등록 화면: 5분 안에 끝나게 (올리기 쉽게)**
1. **"내 가게 찾기"** — 이미 올라온 가게를 검색해서 "내 가게예요"를 눌러요 (처음부터 입력하지 않아요).
2. **체크박스 한 화면** — 할 수 있는 가공을 체크만 해요 (무테·하금·틴팅·편광·고도수·천연 소재… 기존 `CAP_ORDER` 그대로).
3. **가격은 범위로** — 칸마다 슬라이더 또는 "1~2만 원" 같은 고르기 버튼. 직접 숫자 입력은 선택.
4. **작업 기간·택배 여부** — 버튼 두세 개.
5. **동의 체크** — "이 정보를 앱에 공개하는 것에 동의해요" + 언제든 수정·삭제 가능.
6. 사진 올리기(선택), 사업자 인증은 나중 단계로 미뤄요.
- 사장님은 휴대폰 하나로 하는 걸 기본으로 설계하고, 가격 갱신 알림(카카오톡)을 보내서 "오래된 가격" 문제를 줄여요.

### 4-2. 번역: 1차 기계 번역 → 2차 용어 검수 (결정)
- **검수를 쉽게 만드는 법:** 문장 전체를 다 검수하지 말고 **"안경 용어집" 표 하나(약 40개)**를 먼저 만들어서 직접 확인해 주세요. 기계 번역은 그 용어집을 따르게 해요.
- 용어집 초안 예: 무테 Rimless · 하금/반무테 Semi-rimless · 풀림 Full-rim · 틴팅 Tinting · 편광 Polarized · 변색 Photochromic · 블루라이트 차단 Blue-light filtering · 고도수 High prescription · 난시 Astigmatism · 홈파기 Grooving · 구멍 뚫기 Drilling · 비구면 Aspheric · 굴절률 Refractive index · 연마 Edging · 도수 측정 Eye exam.
- 용어가 확정되기 전에는 영어 화면에 한글을 같이 보여 줘서 틀려도 매장에서 통해요.

### 4-3. 후기는 넣어도 될까? (다시 생각)
**후기 자체는 흔한 기능이에요.** 알선처럼 보이는 건 후기보다 아래 경우예요.
| 위험 | 이유 |
|---|---|
| 후기를 쓰면 쿠폰·돈을 주기 | 소개 대가로 보일 수 있고, 광고 표시 의무도 생겨요 |
| 후기를 쓰게 한 뒤 건당 수수료 | 후기가 소개 수단이 돼요 |
| 별점·순위로 앱이 매장을 줄 세우기 | 앱이 특정 매장으로 이끄는 느낌이 돼요 |
| 앱이 마음대로 후기를 지우거나 올리기 | 조작 논란, 명예훼손 분쟁 |

**제안: "후기"보다 "가공 사례 기록"으로 시작해요.**
- 내용: 어떤 프레임에 어떤 가공을 했는지 + 사진 + 걸린 기간 + 실제 낸 비용. **사실 기록 중심**이에요.
- **별점·순위 없음.** 정렬은 거리순·최신순만 해요.
- **대가 없는 글만.** 쿠폰·보상을 주지 않아요. (나중에 주게 되면 "광고/협찬" 표시)
- 작성할 때 **"이 매장에서 가공했어요"** 체크와 얼굴이 나오지 않게 안내 문구를 넣어요.
- **신고·이의 제기** 버튼과 **사장님 답글**을 만들어요. 삭제 기준을 공개해요.
- 수익이 **사장님 도구 구독료**라면 후기와 돈이 연결되지 않아서 더 안전해 보여요.
- MVP에서는 **글 쓰기 기능 없이** 예시 사례 카드 몇 개를 보여 주는 화면만 시연해요. 실제 글쓰기는 법적 확인 후에 열어요.

### 4-4. 가격과 동의 (결정)
- **동의 받는 방식 + 웹에 공개된 안경원 위주로 시작**하는 것에 찬성해요.
- 기본 정보(이름·주소·영업시간·전화)만 "미확인"으로 공개하고, **가격은 사장님 동의 후에만** 보여 줘요. 동의 전에는 지금처럼 "예상 범위(참고용)"으로 보여 줘요.
- 가게 정보를 **삭제·수정 요청하는 창구**를 두고, 요청이 오면 바로 처리해요.
- 팀이 전화로 확인한 정보에는 "확인됨(날짜)"을 같이 적어서 오래되면 흐리게 보여 줘요.

### 4-5. 이 결정이 개발 순서에 미치는 영향
1. (지금 계획된) 사진 찾기 · 보관함 · 조건 카드
2. **사장님 등록 화면 시연** (4-1 흐름, 체크박스 중심)
3. **데이터 신뢰 표시 3단계** 매장 카드·상세에 반영
4. **용어집 40개** 확정 → 영어 버전
5. **가공 사례 카드** (읽기 전용 시연)
